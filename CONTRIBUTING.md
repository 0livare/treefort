# Contributing to Treefort

Thanks for your interest in improving `wt`! This guide covers local setup, the
checks to run before opening a PR, and the project's conventions.

## Prerequisites

> You must have [Bun](https://bun.sh/docs/installation) installed globally.

`wt` runs straight from TypeScript with no build step — the `wt` bin points
directly at `src/main.ts`.

## Local setup

Install dependencies and point the global `wt` command at your local checkout:

```bash
bun install
bun link      # makes `wt` resolve to this local checkout
wt install    # one-time shell wrapper + global gitignore setup
```

After `bun link`, the global `wt` command runs your working copy, so changes are
picked up immediately.

## The PR gate

Before finishing a change, run the typecheck + lint + test gate:

```bash
bun run pr    # tsc typecheck + biome check --write + bun test
```

Individual steps are also available: `bun run types`, `bun run check`,
`bun run lint`, `bun run format`, and `bun run test`. Tests run with
`bun test` — unit tests plus an integration suite (`src/integration.test.ts`)
that drives the CLI as a subprocess against throwaway repos.

## Regenerating the command reference TOC

The **Command reference** section at the bottom of the README opens with a table
of contents generated by [doctoc](https://github.com/thlorenz/doctoc). When you
add, rename, or remove a command, update the reference and regenerate the TOC:

```bash
bun run toc
```

Keep the `<!-- START doctoc -->` / `<!-- END doctoc -->` comment markers in
place — doctoc rewrites everything between them. Because those markers sit at the
top of the last section, the TOC lists only the command headings; don't add new
headings after the reference or they will leak into it.

## Conventions

- **Formatting & linting — Biome** (`biome.json`): no semicolons, single quotes,
  2-space indent, trailing commas, **no bracket spacing** (`{foo}` not
  `{ foo }`), 80-column width. Run `bun run check` to apply.
- Use the `node:` prefix on all Node builtin imports (`node:path`, `node:util`,
  …).
- **Commands** live one-per-file in `src/commands/`, each a named-function
  export re-exported through `src/commands/index.ts`. All `git`/fs work goes
  through `src/git.ts`.
- **The stdout/stderr contract**: a subprocess can't `cd` its parent shell, so
  **stderr** carries all human-facing output (progress, pickers, `list`) and
  **stdout** carries at most one line: a directory path for the `wt` shell
  function to `cd` into. Never print human-facing text to stdout.

## Commits — Conventional Commits

Follow the [Conventional Commits](https://www.conventionalcommits.org) spec:

```
<type>: <short summary>
```

- Common types: `feat`, `fix`, `refactor`, `chore`, `docs`, `test`, `build`.
- Summary in the imperative mood, lowercase, no trailing period.
- Add a body (blank line, then wrapped prose) for non-trivial changes.
- Keep commits atomic: one logical change per commit, each leaving the code
  building.
